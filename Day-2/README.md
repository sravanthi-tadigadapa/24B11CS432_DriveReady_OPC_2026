# Sweet Crumbs Home Bakery Chatbot — Day 2

A Python command-line chatbot for **Sweet Crumbs Home Bakery**. This Day 2 version demonstrates prompt engineering, few-shot message classification, JSON order extraction, price calculation, conversation history, and API error handling.

## Features

- **Bakery menu:** Stores product names and prices in a Python dictionary.
- **System prompt:** Defines the assistant's role, bakery facts, response rules, and language behavior.
- **Few-shot classification:** Classifies customer messages as `order`, `question`, or `complaint`.
- **Order extraction:** Requests structured JSON containing the customer's name, item, quantity, date, and eggless preference.
- **Price calculation:** Calculates item totals and validates the item and quantity.
- **Logging decorator:** Logs calls to the price calculation function.
- **Conversation memory:** Keeps the system prompt and recent chat messages in conversation history.
- **Error handling:** Handles rate-limit, authentication, and connection errors.

## Setup

### 1. Create a virtual environment (recommended)

**Windows PowerShell:**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install the dependency

```bash
pip install openai
```

### 3. Configure the API client

Set the API key required by your model provider. For example:

**Windows PowerShell:**

```powershell
$env:OPENAI_API_KEY="your_api_key"
```

**macOS / Linux:**

```bash
export OPENAI_API_KEY="your_api_key"
```

If `openai/gpt-oss-20b` is hosted by an OpenAI-compatible provider other than OpenAI, configure the SDK with that provider's API key and `base_url`, as specified by the provider.

> **Important:** The supplied `day2.py` calls `client.chat.completions.create(...)`, but it does not define or initialize `client`. Before running the script, add the appropriate `OpenAI` client initialization near the imports. The exact `base_url` and API key variable depend on the provider hosting the model. The model name must also be available from that provider.

Example pattern for an OpenAI-compatible API (replace the placeholders with the provider's actual values):

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("PROVIDER_API_KEY"),
    base_url="https://YOUR_PROVIDER_BASE_URL"
)
```

Do not commit API keys to GitHub or hard-code them in the source file.

### 4. Run the program

```bash
python day2.py
```

The script prints the menu, tests the price calculation, runs a sample message classification, attempts to extract a sample order as JSON, and then starts the interactive chatbot.

Type `exit`, `quit`, or `bye` to stop the chatbot.

## Concepts demonstrated

### 1. Prompt engineering

The `SYSTEM` prompt gives the chatbot its bakery role, menu and prices, business rules, response-length limit, and English/Telugu language behavior.

### 2. Few-shot learning

The `EXAMPLES` list provides sample customer messages and their categories. `classify_message()` sends these examples with a new message and asks the model to return one category.

### 3. JSON extraction

`extract_order()` asks the model to return order details in JSON format, then parses the response with Python's `json.loads()`.

### 4. Decorators

The `log_call` decorator prints a log message before and after the decorated function runs. It is applied to `get_price()`.

### 5. Conversation memory

The `history` list stores the system prompt and chat messages. `MAX_TURNS = 8` limits the messages sent to the model to the system prompt plus the latest 8 user/assistant turns.

### 6. Exception handling

The `chat()` function handles rate-limit, authentication, and API connection errors and returns a user-friendly message.

## Notes and limitations

- The supplied script needs a configured `client` object before any model API call can work.
- The configured model identifier and API endpoint must match the provider being used.
- The message classifier and JSON extraction functions make live model API calls.
- Conversation history is stored in memory only; it is not saved after the program exits.
- The chatbot's replies are generated by an AI model. Verify order details and prices before confirming a real customer order.
